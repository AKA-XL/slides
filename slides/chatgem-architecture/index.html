ChatGEM lets a researcher describe a metabolic-modeling task in plain language. An AI agent turns it into Python that calls real simulation software (COBRApy, StrainDesign, the Gurobi solver), and runs that code in an isolated container. The AI never computes the biology itself. What is ChatGEM? · The core paradigm

ChatGEM = PNNL’s ADEPT platform + a GEM-ready sandbox + a curated script library

The problem

  • FBA, OptKnock, ecGEMs demand COBRApy or MATLAB coding
  • No prior tool runs these simulations conversationally

Three technical pillars

  • Orchestration: ADEPT orchestration service, LangGraph underneath*
  • Simulation: COBRApy, StrainDesign, hand-built Gurobi MILPs
  • Execution: containerized sandbox MCP server; nsjail optional*

* From the ADEPT code (github.com/pnnl/adept-agentic @ 9c603ca), not the paper. nsjail is off by default there. The paper does not say which ADEPT configuration ChatGEM ran.

ChatGEM is not a new framework. It is an application of ADEPT, PNNL's general platform for building scientific AI agents (George et al. 2025, Zenodo 10.5281/zenodo.17315801). ChatGEM "inherits from ADEPT's full architecture" and adds three things: a sandbox with COBRApy, StrainDesign and Gurobi (plus a Gurobi license-manager tool); longer run-time limits for slow strain-design jobs; and a retrieval library of 52 hand-curated example scripts. ADEPT has three tiers: a Keycloak login gateway, an orchestration service that coordinates agents and saves conversations in PostgreSQL, and stateless MCP tool servers. Redis holds tool settings; ChromaDB holds the knowledge base. The AI model is chosen in a config file; ChatGEM defaults to o4-mini. The paper never names LangGraph or nsjail. The ADEPT code does use LangGraph. nsjail is supported there but switched off by default, with a note that it "breaks plot generation", so we can't say ChatGEM used it. Fig. 1 was made with AI assistance, per the paper's AI-usage statement. It matches the text, but treat it as a schematic.

Deterministic safeguard: this holds. The AI writes Python, and COBRApy, StrainDesign and Gurobi do the math inside the sandbox. But note who writes the plan: each benchmark prompt is a human-written lettered protocol (steps A to K) with reaction IDs, bounds and the algorithm already chosen. The AI translates the plan into code; it does not design the analysis. Grounding is the real lever. Without retrieval, models invented software commands (GPT-4.1 made up a "strain_design" package), used the wrong library (Cameo instead of StrainDesign), or wrote broken math constraints. With retrieval they adapted working scripts. Deep dive 3 has the numbers. Human in the loop: the only human step in the paper is a timing condition, "ChatGEM coding with manual inspection" (Fig. 2D–F). There are no approval breakpoints, and no approval code in ADEPT's source. The paper mentions no 4-hour simulations; the longest reported run is 954 s. Agents: the abstract says "specialized agents", but Methods name only ADEPT's Scientific Workflow Agent. The retrieval library is Python scripts, not scientific literature.

Deep dive · The MCP superpower

MCP is the contract between an unpredictable AI and deterministic tools

Tool abstraction

  • BLAST, UniProt, PubChem, Nextflow as MCP tool servers
  • Schemas over JSON-RPC (ADEPT repo)
  • The AI sees typed tools, not raw APIs

Decoupled scaling

  • Servers are stateless; state lives in the orchestrator
  • Swap or scale a server without touching agent logic
  • COBRApy / StrainDesign are not separate servers: they’re installed in the sandbox

Secure execution

  • Generated code goes to the sandbox MCP server
  • Isolated network, non-root, dropped capabilities, CPU/memory caps, egress allowlist, import check
  • nsjail opt-in, off by default; time limit 30 s default, 300 s max

Paper p. 4–5, Methods p. 11–12; sandbox details from github.com/pnnl/adept-agentic @ 9c603ca (sandbox_mcp_server). Plain-language version: deep dives 5 and 6.

The paper describes ADEPT's third tier as "stateless MCP tool servers" that run scientific tools (BLAST, UniProt, PubChem), computing-cluster pipelines (Nextflow), and "sandboxed code on demand". JSON-RPC isn't in the paper, but ADEPT's README says its servers speak the MCP JSON-RPC protocol. One correction to a common description: COBRApy and StrainDesign are not their own MCP servers. They are Python libraries installed in ChatGEM's code environment inside the sandbox. The agent reaches them by writing code, not by calling ready-made tools. That's flexible but less constrained; the takeaways slide returns to this trade-off. Sandbox details come from the ADEPT code: execution in a dedicated container on an isolated network that can reach only the orchestration service, a non-administrator user, removed system permissions, CPU and memory limits, an approved list of network destinations, and a pre-run check that blocks disallowed libraries. nsjail is supported but disabled by default. The default time limit is 30 s with a 300 s maximum, below the 774 s OptKnock run, which is why the authors raised run-time limits.

How the system works · The technical lifecycle

One request to design a strain, end to end: the paper’s OptKnock task

  1. InputUser uploads P. putida iJN1463 and a lettered protocol: OptKnock for succinate, ≤2 knockouts, ≥10% normal growth
  2. RetrieveAgent searches ChromaDB over the 52 curated scripts; finds 44._optknock.py
  3. GenerateScientific Workflow Agent (LangGraph ReAct loop) adapts it into StrainDesign OptKnock code
  4. ExecuteSandbox MCP server runs it with Gurobi; run-time limits raised for long jobs
  5. ReturnPrinted values + Excel export; large outputs go to files, summaries go back to the AI
  6. ReportAgent answers in chat. Separately, an AI judge (Claude Sonnet 4.6) graded the code

Agent-only coding time 774 s; 954 s with manual inspection (Fig. 2E). Step 3 loop and step 5 file handling from the ADEPT repo. The paper has no E. coli / PubChem / JSON-return workflow.

This is Task 2 from the benchmark, the closest real analogue to a "find knockouts for succinate" request. It uses the soil bacterium P. putida KT2440, not E. coli. 1. The prompt is a detailed human protocol: glucose uptake −6 mmol/gDW/h, eight exchanges set to secretion only, at most two knockouts, at least 10% of wild-type growth, nine excluded reactions, and export to Excel. The user also uploads the model and data files. 2. The curated library was uploaded and indexed in ChromaDB. It includes 44._optknock.py, which solves this task on this model. 3. In the ADEPT code, the Scientific Workflow Agent is a LangGraph loop: think, call a tool, read the result, repeat. A guard stops it after 3 repeated identical tool calls in the last 10 messages, or 3 failures of the same tool. 4. Execution is routed to the ChatGEM sandbox container. The OptKnock job is an optimization with yes/no choices (which reactions to cut), solved by Gurobi. 5. Results are printed and exported to Excel. ADEPT writes large tool outputs to files and returns summaries so the AI's working memory stays small. 6. The AI judge is part of the paper's evaluation, not the product. Detail worth knowing: the paper says the code "excluded nine essential reactions from the knockout search". The code actually asks for one solution and discards it afterwards if it contains an excluded reaction, so it can return nothing.

These are recommendations. The "In ChatGEM?" column says what the paper and the ADEPT code actually have. Library: ChatGEM's reliability comes from its 52 working scripts. Anything outside the library is untested. Version and test it, and when benchmarking, hold out tasks that the library doesn't already solve. State: ADEPT saves the conversation and tool outputs to a database, but nothing tracks the metabolic model itself. Make the model ID, current bounds, active knockouts and objective explicit, so every step is reproducible and inspectable. MCP: ChatGEM reaches COBRApy only through free-form code. For frequent jobs, ready-made tools give validated inputs, structured outputs and easy testing. Keep the sandbox for new analyses. Guardrails and approvals: neither exists in ChatGEM. Pydantic appears in ADEPT only for configuration. Check model edits before solving, and pause for human approval before long or destructive jobs. Evaluation: score by running the code and comparing its numbers to known answers, and repeat runs. A single AI judge was inconsistent here. Operations: plan for solver licensing, time limits beyond 300 s, and model and spreadsheet file handling.

Deep dive 1 · The science

A metabolic model is a map of a cell’s chemistry that software can search

What it is

  • A GEM lists every known reaction in an organism
  • FBA finds the best flow through it, e.g. fastest growth
  • OptKnock finds reactions to switch off for more product

Like a city road map: FBA plans the traffic; OptKnock picks roads to close so traffic reaches the factory.

In ChatGEM

  • Model: iJN1463, for the soil bacterium P. putida
  • Goal: more succinate, an industrial chemical
  • Tasks: FBA + knockouts, OptKnock, ecOptMDFPathway

Without it

General principle
  • Candidate designs are tested one by one in the lab
  • Each engineered strain costs time and money to build and test
  • Models narrow many options to a few worth testing
Before the AI, the science it automates. A genome-scale metabolic model (GEM) is a list of all the chemical reactions an organism is known to carry out, reconstructed from its genome. Software can search it. FBA (flux balance analysis) asks: given what goes in (say, glucose), what flow through all these reactions best achieves a goal, such as the fastest growth? OptKnock asks: which reactions could we switch off so the cell is forced to make more of a product we want while still growing? ChatGEM's tasks all use iJN1463, a published model of Pseudomonas putida KT2440, a hardy soil bacterium popular in industrial biotechnology. The target product is succinate, a chemical used to make plastics, solvents and food additives. Without models, every candidate design has to be built and tested in the lab. Models don't replace experiments; they prioritize them. This is general knowledge about metabolic engineering, not something this paper tested.

Deep dive 2 · The AI agent

An agent is an AI that can take actions, check the results, and try again

What it is

  • An LLM predicts text, including computer code
  • An agent puts it in a loop: plan, use a tool, read the result, repeat

A chatbot gives you directions; an agent drives the car and reroutes when a road is closed.

In ChatGEM

  • One Scientific Workflow Agent writes Python and runs it in the sandbox
  • Built as a LangGraph loop (ADEPT code)
  • A guard stops it after 3 repeated or 3 failed tool calls

Without it

General principle
  • A chatbot can only describe code; a person must run it
  • Errors surface only when someone tries the code
  • Any numbers it states come from memory, not calculation
A large language model (LLM) is the AI behind tools like ChatGPT: it predicts text, and code is text. On its own, it can only talk. An agent wraps the model in a loop. It decides on a step, uses a tool (here: running code in the sandbox), reads what happened, and decides the next step. That's what lets ChatGEM actually execute an analysis instead of describing one. In ChatGEM, the paper names one agent, ADEPT's Scientific Workflow Agent. In the ADEPT code it's a LangGraph loop with a safety guard: it stops after 3 identical tool calls in the last 10 messages, or 3 failures of the same tool, so it can't spin forever. Without the agent loop, a person copies the code, runs it, and pastes errors back. The "without" points are general knowledge about chatbots versus agents; the paper didn't test a no-agent version.

Deep dive 3 · RAG: retrieval

RAG turns a closed-book exam into an open-book one

What it is

  • Retrieval-augmented generation: look up references first, then answer
  • References are found by meaning, not exact words

An open-book exam: instead of answering from memory, the AI copies the method from a trusted worked example.

In ChatGEM

  • Library: 52 expert-curated example scripts (the corpus)
  • Stored and searched in ChromaDB
  • The agent adapts the closest script to the request

Without it

From the paper
  • Average score fell from 4.20 to 2.63 (o4-mini) and 2.18 (GPT-4.1)
  • An AI invented a software package that doesn’t exist
  • Another used the wrong library; some code didn’t run
RAG stands for retrieval-augmented generation. Before the AI writes anything, the system searches a reference library for the most relevant material and gives it to the AI. ChromaDB is the database that does the search; it matches by meaning rather than exact keywords. ChatGEM's library is 52 example scripts curated by the authors, covering the kinds of analyses the benchmark asks for. The agent retrieves the closest one and adapts it. Without retrieval, the paper shows clear failures (Supp. Files 1–2): GPT-4.1 invented a "strain_design" package that doesn't exist, o4-mini used Cameo instead of the requested StrainDesign, and the hardest task's code didn't run at all. The next slide has the task-by-task numbers, and one big caveat.

Deep dive 4 · Solvers

The AI writes the recipe; proven math software does the cooking

What it is

  • A solver finds the provably best answer to an optimization problem
  • Deterministic: same input and settings, same answer

The AI writes down the recipe; a calibrated oven, not the AI’s guess, does the baking.

In ChatGEM

  • COBRApy and StrainDesign set up the problem; Gurobi solves it
  • Hard tasks are MILPs: yes/no choices, such as which reactions to cut
  • Every number comes from the solver, not the AI

Without it

General principle
  • LLMs predict plausible text; they don’t solve equations
  • A model with thousands of reactions can’t be optimized by reading
  • Numbers would look right but couldn’t be verified
This is the "deterministic safeguard" from slide 3. An optimization solver is math software that finds the best possible answer to a well-defined problem and can prove it's the best. Given the same input and settings, it gives the same answer every time. In ChatGEM, COBRApy and StrainDesign translate the biology into a math problem, and Gurobi, a commercial solver, solves it. The hardest tasks are mixed-integer problems: some decisions are yes/no (knock this reaction out or not), which makes them much harder to solve. ChatGEM added a Gurobi license-manager tool to its sandbox. Without a solver, you'd be relying on an AI's text prediction to produce flux values for a network with thousands of reactions. That's not what language models do, and there'd be no way to check the result. This is a general principle; the paper didn't test an AI-only version.

Deep dive 5 · The sandbox

A sandbox lets AI-written code run without risking your computer or data

What it is

  • A sealed-off area where untrusted code runs
  • Built from a container: its own files, limited power, restricted network

Like a biosafety cabinet: the work happens inside, and anything hazardous stays inside.

In ChatGEM

ADEPT code
  • No administrator rights; capped CPU and memory
  • Reaches only approved addresses (egress allowlist)
  • Code is checked for blocked libraries before it runs

Without it

General principle
  • AI-written code runs with your permissions: it could delete or leak files
  • A runaway job could freeze the machine
  • One bad script could affect every user on a shared server
AI-written code is untrusted by default: the AI can make mistakes, and a cleverly worded input could trick it into writing something harmful. A sandbox runs that code somewhere it can't do damage. ChatGEM's sandbox is a separate container, a self-contained software package isolated from the rest of the system. In the ADEPT code, it runs without administrator rights, with CPU and memory caps, on a network that can reach only the orchestration service and an approved list of addresses. Before running, it reads the code and blocks libraries that aren't allowed. Time limits default to 30 s (300 s max); ChatGEM raised them for long strain-design jobs. An extra isolation layer, nsjail, exists but is switched off by default. The paper states that code runs in a sandbox container; the specific protections come from the ADEPT code, and the paper doesn't say exactly how ChatGEM configured them. The "without" points are standard security reasoning, not something the paper tested.

Deep dive 6 · MCP

MCP is a universal plug: any tool, any AI model, one standard

What it is

  • Model Context Protocol: an open standard for connecting tools to AI
  • Each tool describes what it does and what inputs it needs

Like USB: one kind of port works for keyboards, drives, and cameras.

In ChatGEM

  • Tool servers for BLAST, UniProt, PubChem, Nextflow, and the sandbox
  • Servers are stateless: restart, copy, or swap them freely
  • COBRApy is not a server; the agent reaches it by writing code

Without it

General principle
  • Every tool is wired into every agent by hand
  • Changing one tool can break the agent’s code
  • Tools can’t be reused across projects or AI models
MCP, the Model Context Protocol, is an open standard for plugging tools into AI systems. Each tool server announces what it can do and what inputs it takes, in a standard format. Any agent that speaks MCP can then use any tool that speaks MCP. In ChatGEM, per the paper, ADEPT's tools run as stateless MCP servers: sequence search (BLAST), protein data (UniProt), chemical data (PubChem), computing-cluster pipelines (Nextflow), and the code sandbox. Stateless means a server keeps no memory between requests, so it can be restarted or copied without losing anything. Important nuance: the metabolic-modeling libraries are not MCP tools. They live inside the sandbox, and the agent uses them by writing code. Without a standard like MCP, each tool needs custom glue code for each agent, and changes ripple through. This is general software-engineering reasoning; the paper didn't compare against a non-MCP version.

Deep dive 7 · The ADEPT platform

ADEPT supplies everything around the agent, so ChatGEM only adds the biology

What it is

  • PNNL’s general platform for building science AI agents
  • Provides login, memory, tools, sandbox, and monitoring

A fully equipped shared lab: ChatGEM brings the experiment, not the building.

In ChatGEM

  • Logins via Keycloak; conversations saved in PostgreSQL
  • AI model picked in a settings file (default o4-mini)
  • ChatGEM adds the modeling sandbox, longer run limits, and the script library

Without it

General principle
  • Each science agent rebuilds security, storage, and tooling from scratch
  • More custom code means more places for bugs
  • Platform improvements don’t reach every project
ADEPT is PNNL's general-purpose platform for scientific AI agents (George et al. 2025). ChatGEM is ADEPT configured for metabolic modeling; it "inherits from ADEPT's full architecture". From the paper: ADEPT provides a login gateway (Keycloak), an orchestration service that coordinates the agent and saves conversations (PostgreSQL), settings storage (Redis), a knowledge base (ChromaDB), tool servers over MCP, activity tracing (Langfuse or LangSmith), a choice of AI providers in a settings file, and a way for separate ADEPT installations to share agents securely. ChatGEM's own additions are small: a sandbox with COBRApy, StrainDesign and Gurobi, a Gurobi license tool, longer run-time limits, and the 52-script library. That's the point: the platform does the heavy lifting. The "without" points are general reasoning about reusable platforms, not something the paper measured.

Deep dive 8 · Human in the loop

In ChatGEM, humans still plan the analysis and check the code

What it is

  • Human in the loop: people review or steer the AI at key points
  • Ranges from writing the plan to approving each action

Autopilot with a pilot in the seat: the system flies, a person sets the route and watches.

In ChatGEM

  • The user writes a step-by-step protocol with exact reaction names
  • A scientist inspects the code: FBA took 3.9 s alone, 184 s with inspection
  • No approval step before runs (none in paper or ADEPT code)

Without it

From the paper
  • No script, even with retrieval, earned a top accuracy score
  • So unchecked AI code would carry those errors into results
Human in the loop means a person stays involved at key points instead of letting the AI run on its own. In ChatGEM, people do two things. First, they write the plan: every benchmark prompt is a detailed, lettered protocol with exact reaction IDs, limits and the algorithm to use. The AI translates it into code; it doesn't design the analysis. Second, they inspect: the paper times "ChatGEM coding with manual inspection" separately. For the simple FBA task that's 3.9 s for the agent alone versus 184 s with a person checking. There's no built-in approval step, where the agent pauses and waits for a yes before running something. Neither the paper nor the ADEPT code has one. Why checking matters, from the paper's own grades: on the accuracy scale, 5 means "runs correctly and follows best practices". Every script scored 4 or lower, even with retrieval. The judge flagged issues in all of them.

Deep dive 9 · Tracing

Tracing records every step the agent takes, so its work can be audited

What it is

  • Logging each AI call, tool call, and result, in order
  • Langfuse / LangSmith show them as a replayable timeline

A flight recorder, or a lab notebook that writes itself.

In ChatGEM

  • ADEPT can trace with Langfuse or LangSmith, plus basic logs
  • The paper reports no traces or chat transcripts
  • So we can’t see how many attempts each task took

Without it

From the paper
  • No one can check how much of the case study the agent did
  • Failures can’t be diagnosed after the fact
Tracing, also called observability, means recording everything the agent does: each prompt to the AI model, each tool call, each result. Tools like Langfuse and LangSmith turn that into a timeline you can replay and search. ADEPT supports both, and the paper cites this for "improved auditability". But the paper doesn't publish any traces or chat transcripts. That gap is visible in the paper itself, which is why this is tagged "From the paper": we can't tell how many attempts each task took, whether the agent retried after errors, or how much of the eight-model case study the agent did versus the authors. With traces released, all of that could be checked.

Deep dive 10 · The AI judge

An AI judge graded the code: fast and cheap, but inconsistent

What it is

  • LLM-as-judge: one AI grades another’s work against a rubric
  • Here: 5 = runs correctly; 3 = runs, wrong output; 1 = doesn’t run

Like a teaching assistant with an answer rubric: quick, but can mark the same answer differently twice.

In ChatGEM

  • Judge: Claude Sonnet 4.6, one pass per script
  • Graded 12 scripts: 3 tasks × with/without RAG × 2 models
  • On identical code, two reports disagreed about a missing column

Instead of it

General principle
  • Human experts: slower, but trusted
  • Execution checks: run the code, compare numbers to a known answer
  • Best: combine them and repeat runs
The paper's scores all come from an AI judge: Claude Sonnet 4.6 read each script and scored accuracy (does it run correctly?) and completeness (does it do everything asked?) from 1 to 5. The combined score weights accuracy 70% and completeness 30%. Twelve scripts were graded: three tasks, with and without retrieval, for two AI models, each once. The judge wasn't fully consistent: o4-mini and GPT-4.1 produced byte-identical code for the retrieval OptKnock task, yet one report says a results column is missing and the other says it's present. It is present. Alternatives are general practice in the field, not something the paper did: have experts grade, or better, run each script and compare its numbers with a known correct answer, and repeat runs to see the variation.

ADEPT
PNNL’s general-purpose platform for building scientific AI agents. It provides logins, conversation memory, tool connections, monitoring, and a safe place to run code. ChatGEM is ADEPT set up for metabolic modeling.
AI agent
An AI that doesn’t just chat: it decides on a step, uses a tool (such as running code), looks at the result, and repeats until the task is done.
API
The set of commands a piece of software offers to programmers. “Inventing an API” means writing code that calls commands that don’t exist.
Benchmark
A fixed set of test tasks used to measure and compare performance. ChatGEM’s benchmark had three metabolic-modeling tasks.
BLAST
A widely used tool that finds DNA or protein sequences similar to a query sequence.
Bounds
The lowest and highest flow each reaction is allowed in a model. Setting both to zero switches a reaction off.
Cameo
Another Python package for strain design. The benchmark task asked for StrainDesign, so using Cameo counted as an error.
Checkpoint
A saved snapshot of the agent’s progress, so a conversation can resume after a pause or crash.
ChromaDB
A database that finds documents by meaning rather than exact words. ChatGEM uses it to find the stored example script closest to the user’s request.
Claude Sonnet 4.6
An AI model made by Anthropic. The paper used it only to grade the code ChatGEM wrote, not to write it.
COBRApy
Free Python software, widely used to build and simulate metabolic models. It runs FBA and related analyses.
Code score (OPS)
The paper’s 1–5 grade for each script: 0.7 × accuracy + 0.3 × completeness, both scored by an AI judge.
Constitutive strain
One of the four engineered P. putida strains in the case study. It always produces dCas12a, a CRISPR protein that can switch genes down without cutting DNA.
Container
A self-contained package of software and its settings that runs isolated from the rest of the computer, like a shipping container for programs.
Correlation (r)
A number from −1 to 1 measuring how closely two measurements rise and fall together. 0 means no relationship, 1 a perfect one; 0.5 is moderate.
Deterministic
Gives the same output every time for the same input. Scientific software is deterministic; AI language models are not.
Dropped capabilities
System permissions removed from the code’s process, so it can’t change network settings, system files, or other programs.
E. coli
Escherichia coli: the most studied lab bacterium. The original brief said ChatGEM used it; the paper actually used P. putida.
ecGEM
Enzyme-constrained GEM: a metabolic model that also accounts for how much enzyme (protein machinery) each reaction needs, since a cell can only make so much protein.
ecOptMDFPathway
The paper’s hardest task: a custom optimization combining enzyme limits with thermodynamics (whether reactions are energetically favorable) to find production pathways.
Egress allowlist
The sandbox may only connect to an approved list of network addresses; every other outgoing connection is blocked.
Enzyme
A protein that speeds up one specific chemical reaction in the cell. Cells can only make so much protein, which limits how fast reactions can run.
Execution-based evaluation
Grading code by running it and comparing its numbers (fluxes, knockout lists) with a known correct answer, instead of having someone read it.
FBA (flux balance analysis)
A calculation that finds how material should flow through a metabolic model’s reactions to reach a goal, such as maximum growth.
Flux
The rate at which material flows through a reaction, for example millimoles per gram of cells per hour.
GEM (genome-scale metabolic model)
A computer map of all the chemical reactions an organism is known to carry out, built from its genome. Used to predict growth and what the cell can produce.
Glucose uptake
How fast the modeled cell takes in glucose, its sugar food source. Setting it to 0 starves the model cell, so it can’t grow.
GPT-4.1
An OpenAI language model, compared against o4-mini in the paper.
Guardrails
Automatic checks that stop an AI from taking invalid or unsafe actions, such as editing a reaction that doesn’t exist.
Gurobi
A commercial optimization solver: the engine that actually does the math, finding the best answer to large optimization problems.
Held-out tasks
Test tasks deliberately kept out of the reference library, to check whether the AI can handle something genuinely new.
Human in the loop
A person reviews or steers the AI at key points instead of letting it run fully on its own.
iJN1463
A published, widely used metabolic model of the bacterium Pseudomonas putida KT2440. All of the paper’s tasks use it.
Import check
Before running, the sandbox reads the code and blocks any software libraries that aren’t allowed.
interrupt()
LangGraph’s built-in pause: the agent stops and waits for a person to approve before continuing.
JSON-RPC
A simple, standard message format for one program to ask another to do something and get a structured answer back.
Keycloak
Open-source software that handles logins and controls who can access what.
Knockout
Switching off a gene or reaction, in the model or in the real organism, to see how the cell responds.
Langfuse / LangSmith
Monitoring tools that record every AI call and tool result, so you can replay and audit what an agent did.
LangGraph
Open-source software for building AI agents as a flowchart of steps (think, use a tool, check, repeat), with progress saved between steps.
LLM (large language model)
The kind of AI behind chatbots like ChatGPT. It predicts text, including computer code, from patterns learned in training, and can sound confident while being wrong.
LLM wrapper
A thin app that passes your question to an AI model and shows its reply, with no tools, checks, or reference material.
LLM-as-judge
Using one AI model to grade another’s output against a rubric. Fast and cheap, but it can be inconsistent.
MATLAB
Commercial programming software popular in engineering. The original COBRA Toolbox for metabolic modeling runs on it.
MCP (Model Context Protocol)
An open standard for plugging tools into AI systems, like USB for AI. Any tool that speaks MCP can be used by any agent that speaks MCP.
MILP
Mixed-integer linear program: an optimization problem where some choices are yes/no, such as whether to knock a reaction out. Hard to solve; needs a specialized solver.
Nextflow
Software for running multi-step data-analysis pipelines on large computing clusters.
Non-root
Runs without administrator rights, so the code can’t change the system it runs on.
nsjail
An extra isolation layer (a “jail”) for running untrusted programs on Linux. ADEPT supports it, but it’s switched off by default.
o4-mini
A smaller, cheaper OpenAI language model. It’s ChatGEM’s default.
Objective
The quantity an optimization tries to maximize or minimize, such as growth rate or product output.
Optimization
Finding the best choice among all allowed options, for example the reaction flows that give the fastest growth.
OptKnock
An algorithm that searches for reactions to switch off so a microbe is forced to make more of a desired product while still growing.
Orchestration
The coordinating layer that decides which step or tool runs next and keeps track of the conversation.
PNNL
Pacific Northwest National Laboratory, a US Department of Energy research lab, where ChatGEM and ADEPT were built.
PostgreSQL
A widely used database. ADEPT stores conversations and agent checkpoints in it.
Preprint
A paper shared publicly before peer review. bioRxiv is the main preprint server for biology.
Proteomics
Measuring which proteins are present in cells, and how much of each.
Pseudomonas putida
A hardy soil bacterium popular in industrial biotechnology. The paper uses strain KT2440.
PubChem
A large public database of chemical compounds and their properties.
Pydantic
A Python tool that checks data against rules (right type, allowed values) and rejects anything that doesn’t fit.
Python
The programming language most scientific and AI software is written in, including COBRApy and StrainDesign.
RAG (retrieval-augmented generation)
Before answering, the AI looks up relevant reference material and uses it: an open-book exam instead of answering from memory.
ReAct loop
A common agent pattern that alternates reasoning (“what next?”) with acting (calling a tool), then reads the result and repeats.
Rubric
A scoring guide that spells out what earns each grade.
Sandbox
A sealed-off area where AI-written code runs. If the code is wrong or harmful, the damage stays inside: it can’t touch your files, freely reach the internet, or use unlimited computing power.
Schema
A formal description of what inputs a tool accepts and what it returns, so an AI can call it correctly.
Scientific Workflow Agent
ADEPT’s general-purpose agent that writes and runs scientific code. It’s the only agent the paper names.
Script library (corpus)
The 52 example scripts, curated by the authors, that ChatGEM searches before writing code. Its coverage decides what the agent can do reliably.
Solver
Math software that finds the best possible answer to a well-defined optimization problem, and can prove it’s the best.
Stateless
Keeps no memory between requests. Each call is self-contained, so the server can be restarted or copied without losing anything.
Strain
A genetically distinct version of an organism, such as a microbe engineered to make more of a chemical.
StrainDesign
Python software that finds genetic changes, such as knockouts, to engineer a microbe toward a goal. OptKnock is one of its methods.
Succinate
Succinic acid: a chemical cells make naturally, used industrially for plastics, solvents, and food additives. A common target for microbial production.
Succinate leakage index
A ratio the authors defined: enzyme use at the step that consumes succinate, divided by two steps that produce it. In the paper, lower values mark strains expected to excrete more succinate.
Syntax error
A grammar mistake in code, like a missing bracket. It stops the program from running at all.
Titer
How much product has accumulated in the culture, for example grams of succinate per liter.
UniProt
The main public database of protein sequences and their functions.
Wild type (WT)
The unmodified, natural strain that engineered strains are compared against.
